# WOLF AI 17.3 — аудит реальной реализации и безопасные исправления

Документ сверяет рекомендации по Security, Java/Python, LLM, API и CI
с конкретными исходниками; не выдаёт бумажную схему за рабочую функцию.

## 1. Пароли, Accessibility и локальная история

- **Accessibility**: `WolfAccessibilityService.hasSensitiveField()`
  проверяет видимые `password`, `textPassword`, `textVisiblePassword`,
  `textWebPassword`, цифровые PIN-поля, не извлекая их текст.
  При наличии такого элемента WOLF **отказывает во всех дальнейших
  действиях на текущем экране**: список кнопок/клик/маршрут/прокрутка.
  При превышении ограничителя 450 элементов проверка завершается
  отказом, а не попыткой кликнуть.
- **ChatStore**: `SensitiveText.forStorage` маскирует узнаваемые
  GitHub PAT, `hf_...`, ключи `sk-...`, Bearer, `password=...`,
  `access_token`, `refresh_token` до записи в SQLite.
  На чтении/экспорте зашифрованного архива `.wolfpack` текст
  повторно очищается; старые строки best-effort исправляются при
  следующем открытии writable SQLite. Для SQLite включён
  `PRAGMA secure_delete=ON` (не гарантия удаления физических копий
  на flash/WAL или у провайдера резервных копий).
- **TaskStore**: токены не должны сохраняться в журнале новых задач,
  скрыто отправляться в публичные GitHub Issues или импортироваться
  с резервной копией.
- **Ограничение**: это НЕ распознавание всей личной информации и
  всех возможных секретов. Особенно важные данные не нужно
  вставлять в чат. В чужом приложении пароль может находиться
  в произвольной кастомной UI-области, которую Android не маркирует.

## 2. Android Keystore, StrongBox, биометрия и переносимые архивы

`SecureStore`, `CloudBrainStore` и `MetricoolOAuth` используют
**Android Keystore + AES-GCM**, то есть ключи не выгружаются приложением
как обычные файлы. Для GitHub PAT доступна диагностика
`SecureStore.isHardwareBacked()`, основанная на фактическом
`KeyInfo.isInsideSecureHardware()`; это именно проверка, а
**не обещание StrongBox** для всех устройств.

Нельзя просто включить `setUserAuthenticationRequired(true)`
для существующих ключей: это изменило бы правила доступа,
могло обесценить уже зашифрованные токены и сломать фоновый
OAuth-refresh/GitHub-задания при выключенном экране. Такая
биометрическая политика потребует отдельной пользовательской
опции и плановой миграции/повторной авторизации.

`WorkspaceCrypto` **намеренно не использует Android Keystore**:
`.wolfpack` — переносимая, защищённая пользовательским паролем
резервная копия; аппаратная привязка сделала бы невозможным
восстановление на другом телефоне. Используется PBKDF2-HMAC-SHA256,
случайная соль, AES-GCM и контроль целостности. Менять формат
без мигратора нельзя.

## 3. Общий контракт Android ↔ Python

`contracts/agent_dispatch_v1.json` задаёт точный набор:
`project` (шесть одобренных репозиториев), `mode` (audit/test),
`client_task_id` и параметры `goal`/`safe_fix`.
`wolf_ai/dispatch_contract.py` валидирует поле/тип/значение
на Python; `CommandParser`, `GithubApi` и `TaskStore`
проверяют значения на Android. Интеграционные тесты сверяют
белый список Java и JSON с Python на реальных данных.

Нельзя безопасно считать, что всё, что написал LLM, — исполняемая
команда. Подтверждение инструментов сохраняется отдельно.

## 4. Идемпотентность и сеть

В исходной `MainActivity.dispatchTask` возможен был повтор:
`GithubApi.dispatch(...)` → таймаут **после принятия GitHub**
→ локальная задача оставалась `draft` → повторная POST отправка.
В 17.3 перед POST сохраняется атомарное `reserved`; после успеха —
`submitted`, после любого неустановленного результата —
`dispatch_unknown`. Возврат в `draft` не происходит.
Для быстрого ручного запуска также создаётся локальное задание.

`SafeNetworkRetry` повторяет максимум два раза **только
читающий GET** для HTTP 429/502/503/504 и сетевого таймаута,
с задержкой 250/500 мс. Нет автоматических повторов
`workflow_dispatch`, OAuth POST, публикаций и других
неидемпотентных операций. Неизвестные результаты нуждаются
в проверке на сервере, а не в слепом повторе.

`MetricoolOAuth.accessToken` **уже имел OAuth refresh**.
Теперь обновление токена синхронизировано, refresh token
сохраняется при отсутствии новой версии, шифрованная запись
проверяется через `commit()`, а истёкшая авторизация без
refresh токена вызывает понятную ошибку вместо удаления профиля.
Интеграция по-прежнему зависит от поддержки OAuth на Metricool.

## 5. RAM, нагрев, батарея и локальная нейросеть

`LocalResourceGuard` читает RAM, `lowMemory` Android,
термостатус и заряд батареи на телефоне. `LocalResourcePolicy`
ограничивает глубину и бюджет токенов при предупреждении или
перегреве; тяжёлая GGUF временно заменяется встроенной Qwen 0.5B,
без удаления скачанного файла или изменения платных настроек.

При уходе WOLF в фон и при сигнале Android low-memory
`EmbeddedAi.unloadWhenIdle()` освобождает модель в отдельном
потоке. Нативная загрузка/декодирование **может блокировать
мьютекс**, поэтому это не гарантирует мгновенного освобождения.
У Android по-прежнему есть право завершить процесс при OOM.

**Важное продуктовое решение:** падение локальной модели НЕ
вызывает автоматическую отправку личного вопроса в
`HfBrainClient`: пользователь выбрал режим 0 ₽, а сторонний
провайдер может потребовать оплату и передать контент наружу.
Облачная модель запускается только по отдельной команде
и подтверждению.

## 6. CI/CD и тестовое покрытие

Новые реальные JVM-тесты: `WolfPrivacyResourceTest.java`
(секреты, InputType-пароли, RAM/нагрев/батарея, лимиты сети,
строгие Java-команды). Новые Python-тесты:
`test_wolf_runtime_safety_v17_3.py`
(политика, схема, статусы резервирования, OAuth, безопасность).

Существующие регрессионные тесты по версиям не удалены:
ими уже ловились ошибки обновлений и зависаний. Их
параметризация имеет смысл после отдельной ревизии покрытия.
`wolf-ai-android.yml` выполняет полный Python-набор
**одним проходом**; `gradle/actions/setup-gradle@v4`
уже кэширует Gradle. Никаких новых платных сервисов.

Семь workflows остаются разделёнными по правам. Объединение
`wolf-ai-repair.yml` (contents:write) и
`wolf-ai-audit.yml` (contents:read) в один общий
привилегированный job было бы регрессией безопасности.

## Что ещё нельзя объявить готовым

- Физический тест APK на Samsung и температурный профайлинг.
- Универсальная защита от всех форм персональной информации.
- Обязательная биометрия на каждом секретном действии: нужна
  миграция хранилища и вариант работы при заблокированном экране.
- Проверка реальных OAuth токенов без доступа к аккаунту Metricool.
- Автоматическая бесплатная удалённая замена слабой локальной LLM:
  такой неограниченной бесплатной гарантированной инфраструктуры нет.
